# AGENTS.md

This file provides guidance to AI coding agents when working with code in this
repository.

## Scope

Danish-language Starlight (Astro 7) documentation site for teachers at
Strandgårdskolen / Ishøj Kommune, deployed to `docs.edbpede.net` via GitHub
Pages. All content, headings and UI strings are Danish — write new content in
Danish, not English.

## Commands

Bun is the package manager (pinned `bun@1.3.14` via `packageManager`; CI uses
`bun install --frozen-lockfile`).

```bash
bun run dev      # dev server on :4321
bun run check    # astro check — typecheck + content diagnostics
bun run build    # -> dist/
bun run preview  # serve the built site
bun run lint     # biome check .   (format + lint, non-writing)
bun run lint:fix # biome check --write .
bun run sync     # regenerate .astro/ types after content.config.ts changes
```

There is no test runner and no test files in this repo. "Verified" here means
`bun run lint && bun run check && bun run build` all pass. CI adds `bunx biome
ci .`, the repo's own prek hooks, and a build-serve-curl smoke test asserting
that `/`, `/google-drev/` and `/meebook/` return a `<title>`
(`.github/workflows/smoke.yml`).

## Repository invariants

- There is no `src/pages/`. Every route is generated by Starlight from the
  `docs` content collection. To add a page, add an `.mdx` file under
  `src/content/docs/<kategori>/`; do not create `src/pages/`.
- `.astro/` and `dist/` are generated and gitignored. Never hand-edit them —
  run `bun run sync` (types) or `bun run build` (output).
- A file's path under `src/content/docs/` **is** its public URL. Old GitBook
  URLs are kept alive by the `gitbookRedirects` map at the top of
  `astro.config.mjs`; when you rename or move a guide, update that map in the
  same change.
- A new category directory must be added by hand to the `sidebar` array in
  `astro.config.mjs`. Guides *within* a category are autogenerated from the
  directory, so individual pages need no config change.
- The landing page's situation cards are a hardcoded `situations` array in
  `src/components/SituationCards.astro` — it is not derived from the content
  tree, so a new entry point has to be added there explicitly.
- Screenshots live in `public/screens/` and are referenced from MDX by absolute
  path (`/screens/foo.png`, often as raw `<img class="edb-inline">`).
  `src/assets/` holds only the brand SVG — keep new screenshots in
  `public/screens/` rather than moving them to `src/assets` or switching to
  `<Image>`.
- prek's `check-added-large-files` caps newly added files at 500 KB. Compress
  or resize a screenshot before committing instead of raising the cap.

## Styling

- `src/styles/theme.css` is the single global stylesheet (loaded through
  Starlight `customCss`) and owns the `--edb-*` design tokens plus all
  Starlight overrides. Add global rules there, not in a new stylesheet.
- UnoCSS's reset is disabled in **two** places that must stay in sync:
  `preflights: { reset: false }` in `uno.config.ts` and `injectReset: false` in
  `astro.config.mjs`. Starlight owns the base/reset layer. Note that
  `.agents/rules/astro-dev-pro.md` recommends `presetWind4({ reset: true })` —
  this repo deliberately differs; do not "fix" it toward the rule file.
- Svelte islands carry their own scoped `<style>`. The Solid island
  (`src/components/islands/StepChecklist.tsx`) cannot, so its `.sc__*` classes
  are defined in `theme.css` — put styles for any new `.tsx` island there too.

## Git

- prek's `no-commit-to-branch` blocks committing directly to `main` — branch
  first, then open a PR.
- Commit messages are enforced at the `commit-msg` stage by
  `conventional-pre-commit`; use Conventional Commits.
- `bun run check` runs again as a `pre-push` hook, so a type error fails the
  push, not just CI.

## Reference

- `.agents/rules/astro-dev-pro.md` — Astro 7 / Bun / UnoCSS presetWind4 /
  Svelte 5 runes / SolidJS island conventions, hydration directives and an
  anti-pattern table. Read before writing or editing any component, island, or
  `astro.config.mjs`.
- `README.md` — the shared guide template every `.mdx` follows (frontmatter

  `## Relaterede guides` with `<LinkCard>`). Read before adding or
  restructuring a guide.
