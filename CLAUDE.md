# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A Danish-language Astro 7 + Starlight documentation site (`guides.edbpede.net`) holding
IT guides for teachers. All user-facing copy is Danish; keep it that way. There is no
test suite — the validation gate is type-check plus build.

## Essential Commands

Run from the repository root. `bun` is the package manager (pinned via `packageManager` in `package.json`).

```bash
bun install                # install dependencies (use --frozen-lockfile in CI-like runs)
bun run dev                # dev server on http://localhost:4321
bun run check              # astro check — TypeScript + Astro/MDX diagnostics
bun run build              # production build into dist/
bun run preview            # serve the built dist/
bun run lint               # biome check . (format + lint, read-only)
bun run lint:fix           # biome check --write . (applies formatting and safe fixes)
bun run sync               # regenerate .astro/ types after content-schema changes
```

Fast pre-commit loop: `bun run lint && bun run check`. Full local gate:
`bunx biome ci . && bun run check && bun run build`. CI additionally replays the repo's
own prek hooks (`.github/workflows/code-quality.yml`).

## Architecture Overview

There is **no `src/pages/` directory**. Every route is generated by Starlight from the
`docs` content collection declared in `src/content.config.ts` (`docsLoader()` +
`docsSchema()`). A file at `src/content/docs/<kategori>/<slug>.mdx` becomes
`/<kategori>/<slug>/`. Adding a page is therefore a content operation, not a routing one.

`astro.config.mjs` is the single wiring point and holds three things that must stay in
sync with content: the `sidebar` category list, the `gitbookRedirects` map preserving
old GitBook URLs, and the Starlight component `overrides`.

Rendering is zero-JS by default. Interactivity lives in two islands under
`src/components/islands/` — `Kodeordshjaelper.svelte` (Svelte 5 runes) and
`StepChecklist.tsx` (SolidJS) — imported directly into MDX with `client:visible`. The
islands hydrate independently and share no parent tree, so they hold no shared state.

Styling has two layers: `src/styles/theme.css` owns the design tokens (`--edb-*`) and
overrides Starlight's `--sl-color-*` scales for both themes, and UnoCSS `presetWind4`
supplies atomic utilities for custom components only. `uno.config.ts` disables the
preset reset because Starlight owns the global base layer.

## Project Boundaries

| Path | Role |
| --- | --- |
| `src/content/docs/` | All guides. One directory per sidebar category. |
| `src/components/` | Astro components (`SituationCards`, `Embed`). |
| `src/components/islands/` | The only place client-side JS belongs. |
| `src/components/overrides/` | Starlight component overrides; must be registered in `astro.config.mjs`. |
| `public/screens/` | Guide screenshots, referenced as absolute `/screens/...` paths. |
| `src/styles/theme.css` | Design tokens and all `.edb-*` component styles. |
| `dist/`, `.astro/`, `node_modules/` | Generated or vendored; never edit. `.astro/` is regenerated by `bun run sync`. |

## Common Change Workflows

**Add a guide to an existing category**

1. Create `src/content/docs/<kategori>/<slug>.mdx`. The filename becomes the URL slug —
   use lowercase ASCII (`sadan-skifter-du-kode-pa-uni-login`, not `sådan-…`).
2. Frontmatter needs `title`, `description`, and `sidebar.order`; add `sidebar.label`
   when the sidebar entry should read shorter than the page title.
3. Follow the established page template: short intro, `<Aside type="note"
   title="Hvornår skal du bruge denne guide?">`, `<Steps>` with numbered steps and
   images, a `## Hvis det ikke virker` section using `<details class="edb-trouble">`,
   and `## Relaterede guides` with `<CardGrid>` + `<LinkCard>`.
4. Put screenshots in `public/screens/` and reference them inline as
   `<img src="/screens/…" class="edb-inline" alt="…" />`.
5. Run `bun run check && bun run lint`.

**Add a new category**

1. Create the directory plus an `index.mdx` with `sidebar: { label: "Oversigt", order: 0 }`.
2. Add a `{ label: …, collapsed: true, items: [{ autogenerate: { directory: "<dir>" } }] }`
   entry to the `sidebar` array in `astro.config.mjs`. Individual pages are never listed
   there — autogeneration handles them.

**Rename or move a published guide**

Add the old path → new path pair to `gitbookRedirects` in `astro.config.mjs`. Published
links are live; a rename without a redirect breaks them.

**Add interactivity**

Put the component in `src/components/islands/`, import it in the MDX file with a relative
path, and hydrate with `client:visible` (the directive both existing islands use).

## Implementation Decisions

| Situation | Preferred approach | Avoid |
| --- | --- | --- |
| Reusable interactive widget | Svelte 5 runes or Solid island under `islands/`, `client:visible` | Inline `<script>` in MDX |
| Layout/utility styling in a custom component | UnoCSS utility classes referencing `var(--sl-color-*)` / `var(--edb-*)` | Hardcoded hex colours |
| Styling that guides use via a class name (`.edb-trouble`, `.edb-inline`) | Add it to `src/styles/theme.css` | Scoped `<style>` in each MDX file |
| Changing Starlight chrome (footer, page frame) | Wrap the default component in `src/components/overrides/` and register it | Forking Starlight markup wholesale |
| Embedding a video | `src/components/Embed.astro` | Raw `<iframe>` |

## Repository Conventions

- Biome is the formatter and linter: 2-space indent, 100-char lines, double quotes,
  always semicolons, trailing commas. `noUnusedImports` and `noUnusedVariables` are
  deliberately off — do not "fix" unused imports in MDX-adjacent files on that basis.
- Commit messages must be Conventional Commits; `prek`'s `conventional-pre-commit` hook
  enforces this at `commit-msg`.
- Danish slugs drop diacritics (`å`→`a`, `æ`→`ae`, `ø`→`o`), matching both existing
  filenames and the redirect map.
- Non-obvious decisions are documented as comments in the config files themselves
  (`uno.config.ts`, the CI workflows, `astro.config.mjs`). Extend those comments rather
  than moving the rationale elsewhere.

## Testing and Validation

There are no unit or browser tests. Validation is three layers:

1. `bunx biome ci .` — format and lint, non-writing.
2. `bun run check` — Astro/TypeScript diagnostics. Also runs as a `pre-push` prek hook.
3. `bun run build` plus the smoke test in `.github/workflows/smoke.yml`, which serves
   `dist/` and asserts `/`, `/google-drev/`, and `/meebook/` return a `<title>`.

The smoke test is intentionally not a browser test: a prerendered page returns 200 with a
valid `<title>` even when island hydration is broken. Verify island changes by hand with
`bun run dev`.

## Critical Gotchas

- `prek`'s `no-commit-to-branch` hook blocks direct commits to `main`. Work on a feature
  branch and open a PR; `code-quality.yml` and `smoke.yml` gate pull requests. Use
  `git commit --no-verify` only when a maintainer has explicitly asked for a direct
  commit to `main`.
- `check-added-large-files` caps additions at 500 KB. Compress screenshots before adding
  them to `public/screens/`.
- The canonical production host is `https://docs.edbpede.net`. Keep the `site` value in
  `astro.config.mjs` and the `cname` value in `.github/workflows/deploy.yml` aligned.
- The sidebar-collapse state is restored by an inline script in the `head` array of
  `astro.config.mjs` and consumed by `src/components/overrides/PageFrame.astro`. Changing
  the `edb-sidebar-collapsed` localStorage key or the
  `data-edb-sidebar-collapsed` attribute requires editing both.
- After editing `src/content.config.ts`, run `bun run sync` before `bun run check`;
  otherwise `.astro/` types are stale and diagnostics are misleading.
